The first couple of commands are drop and create statements. These commands are used to drop any tables that bear the same name as the ones we want to create (to help prevent multiple instances of the same table). We then use the create table statements to create tables for students, for courses, for enrollments, and for the enrollment audit. Next, we have our insert statements in order to insert data for our functions. We run this to insert the students, the enrollments, and the courses as well, to ensure that we at least have some data to play with in our system. Next, we have our update statements to accurately set the enrolled count equal to the number of students we have enrolled in their respective courses. Our next few commands are used to grant privileges to the user roles we created. We grant select access to the three major tables for our advisor and registrar roles. We also ensure that we give some transactional privileges to our registrar roles for some tables and revoke their ability to delete enrollments. Our next command is then used to ensure that we can see all the privileges both roles have and on what tables they have them as well. We then create a procedure for registering students, and this procedure will first check if the student exists, check if the course exists, check if the student is already in the course, and then finally check if there is still room in that course. If it passes all these tests, then the student will be added to the class, and the number enrolled in that class will be incremented by one. The next two commands are meant to create a trigger function that creates an enrollment audit whenever an enrollment is made, and the audit will use the values of the enrollment that was made. The last for sql statments or groups of statements are just meant to select and show us values for classes and their remaining seats, the enrollments audits in order of time created, a list of privileges for the registrar and advisor, and finally, an enrollment list as well.
